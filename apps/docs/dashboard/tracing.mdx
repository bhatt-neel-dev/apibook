Every request through the APILens middleware gets a trace, automatically. There is no span API to learn and nothing to instrument by hand: the SDK opens a root span per request, turns outbound `requests`/`httpx` calls into child spans, and stitches traces across your services via the W3C `traceparent` header.

## The waterfall

The **Trace** tab of any request shows its spans as a waterfall: each bar's position is when the step started, its length is how long it took. Spans are colored by kind — server (teal), outbound HTTP (blue), database (amber) — and any failed span turns red.

Because `traceparent` propagates on outbound calls, a request that hops `cart-service → payment-service → orders-api` renders as **one trace**, as long as each service runs the APILens middleware.

## Exceptions: errors capture themselves

When a request raises an unhandled exception or returns a 5xx, the SDK records exactly one `ERROR` record on the trace:

- an unhandled exception attaches the **full stack trace**,
- a plain 5xx records `HTTP <code> on <method> <path>`.

These land in the request's **Exceptions** tab — the tab carries a count badge so you see *that* and *how many* without opening it, and the first traceback arrives already expanded, with one-click copy. The Trace tab cross-references them: each failing span in the waterfall carries a red *exception* chip that expands its correlated exception inline, right under the span.

That means the answer to "why did this 500?" is usually already sitting in the modal — no log-diving, no correlating timestamps across systems.

<Note>
A clean request has no exceptions and no badge. This is not a general-purpose logging API — it is deliberately scoped to errors, so the signal-to-noise ratio stays high.
</Note>

## Controlling trace capture

Tracing is on by default whenever an `app_id` is set. Two levels of control:

```python
# per-app, in code
app.add_middleware(ApiLensMiddleware, ..., capture_spans=False)
```

```bash
# deploy-time kill switch — overrides code, can only turn tracing OFF
APILENS_CAPTURE_SPANS=false
```

Spans carry timing and endpoint/URL names only — never payloads. The SDK's own telemetry uploads are excluded from tracing. Full details in [SDK tracing reference](/sdk-reference/tracing).

## Already using OpenTelemetry?

If you have an existing OTel setup, attach APILens as an exporter instead of using the built-in tracer:

```python
from apilens import install_apilens_exporter

install_apilens_exporter(client, app_id="orders-api")
```
