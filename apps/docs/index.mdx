APILens is an API observability platform built around one idea: **you run more than one service**. Group all the APIs that belong to a product into a single project, monitor them side by side, and drill from a traffic spike down to the exact request — with its headers, payload, trace waterfall, and stack trace — in a couple of clicks.

## What makes APILens different

- **Projects contain apps.** One project-level API key covers every service in your product. Attribute traffic per app with `app_id`, then filter any page by app.
- **Client vs server errors are separate, everywhere.** A spike in `4xx` (someone misusing your API) is a different problem from a spike in `5xx` (your bug). APILens never blends them into one "error rate".
- **Tracing is automatic.** Every request gets a trace; outbound `requests`/`httpx` calls become child spans; unhandled exceptions and 5xx responses attach a stack trace to the request — with zero extra code.
- **Consumers are explicit.** APILens never guesses identity from auth headers. You tell it who the consumer is; it never reads your tokens.
- **The dashboard is live.** Pages poll every few seconds with a rolling window — no refresh button mashing during an incident.

## Get started

<Steps>
  <Step title="Create a project and app">
    Sign in at [app.apilens.ai](https://app.apilens.ai), create a project, add an app for each service, and generate an API key in **Settings → API keys**.
  </Step>
  <Step title="Add the middleware">
    Install the SDK and add two lines to your service. Pick your framework below for exact instructions.
  </Step>
  <Step title="Watch data arrive">
    Deploy (or just run locally) and send a few requests. Metrics, logs, and traces appear on the dashboard within seconds.
  </Step>
</Steps>
